# Windows CI evidence selection and transport

The historical .306 manifesto and incomplete ZIP remain unchanged. Its 1,261 missing paths are pinned Wine source/build metadata: 1,255 .gitignore, three .gitattributes, one .editorconfig, one .gitlab-ci.yml and one .mailmap. Wine tools/makedep.c:4882 generates .gitignore during in-tree build; their historical contents were not recovered. The other names can be inspected in the original pinned tarball. This policy explicitly admits those metadata names, plus `.evidence` synthetic control directories. Other hidden paths are excluded before the new manifest is sealed; an explicitly required file cannot be excluded to pass collection.

Only `ci-evidence-sources.json` origins enter the single C:/he upload root. Common public source/build receipts remain admitted. Private suffixes (.pfx/.p12/.key/.pem/.dmp/.dump), credential/auth/Git/cargo/cloud configuration directories, disposable dependency venvs and unadmitted hidden names are excluded with path and reason in the new manifest. Explicit authentication filenames and bearer/credential fields, private-key signatures and supported GitHub token formats are excluded; this is a bounded policy, not a universal secret detector. A required direct input, required mandatoryFiles entry, reparse/symlink, missing required origin, or required origin with no admitted files fails collection. No exclusion changes the historical manifest or overrides source-stage obligations.

Public metadata containing actual private material fails admission or is excluded before sealing; no secret contents enter receipts. The synthetic `.pfx` fixture is deliberately excluded. All uploads pass an admission gate, use include-hidden-files=true on their selected output root, and download their real named artifact in the same job for exact-set, size and SHA-256 comparison. Evidence roots use the collector manifest; product roots retain their existing artifact identity and are independently snapshotted outside the payload before upload. Unexpected/absent/tampered files fail the real roundtrip gate. Snapshot identity is tied to head/run/attempt. Producer failure, collection outcome, upload outcome and roundtrip outcome remain separate. Failure evidence still runs with always(); admission failure prevents unsafe upload.

Native Python tests consume CPython 3.12.10 x64 from setup-python's literal pythonLocation/python.exe. PyYAML 6.0.2 CP312 win_amd64 is pinned by URL and SHA-256 in python-test-pins.json and hash-required requirements. Bootstrap invokes that interpreter's -m pip; it never imports MSYS2 site-packages. Before/after receipts contain sys.executable, prefix/base_prefix, paths and relevant preparation environment, package version/import path, acquired wheel identity, and controlled YAML read. The RED control creates a disposable venv without inherited site-packages, runs the actual .306 method-local YAML consumer, then uses the same bootstrap and executes all ci/windows Python tests plus tools/test_candidate_version.py. Product invokes the bootstrap after VS environment initialization and reruns those suites before native DXVK/Release.

No Linux-host reproducibility, GPU or VM qualification is implied.

R4 filesystem admission checks every lexical path component with lstat before expansion, descent, file-content selection or copying. Windows FILE_ATTRIBUTE_REPARSE_POINT (0x400), junctions and POSIX symlinks are refused for selected origins, ancestors, glob results, recursion and the complete verify tree. Component-wise glob expansion and explicit scandir traversal avoid descending through rejected entries; selected optional origins fail too. Receipts record the first refusal, logical source, requested path, rejected component, stage, attributes and reparse tag without reading target contents.

Final file reads use O_NOFOLLOW on POSIX and CreateFileW with OPEN_REPARSE_POINT on Windows, with handle attribute checks and write/delete sharing denied during the read. Supported object identities, size/mtime and source/destination SHA-256 checks detect observed replacement/change. Output files are created exclusively and output parents are checked. These checks do not pin every ancestor directory by relative handles throughout the transaction; concurrent ancestor replacement remains a TOCTOU limitation. R4 does not claim complete protection against malicious concurrent filesystem mutation. No absolute-path resolution is used to hide reparse entries.
